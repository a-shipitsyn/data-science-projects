# Debt payment likelihood

Predict the probability that a debtor makes a payment within the next 3, 6 and
12 months, and the expected amount paid, from debt, income and payment-history
features, with financial-ratio feature engineering and gradient boosting.

## Task

Each record is a snapshot of one debtor: age of the debt case, interest rate,
remaining principal, principal with accrued interest, total balance, debtor age,
income over the last year, total debt held with other creditors, and amounts paid
over the past 3, 6 and 12 months. Values may be missing.

Targets: **1 — the debtor makes a payment within the next 3 / 6 / 12 months, 0 — no
payment**, and the amount paid in each period. Payers are a small minority, so the
classes are strongly imbalanced. Build a model that estimates the likelihood of
payment, so that collection efforts can be planned, and explain the data
preparation and modelling choices.

No original data is included in this repository. It uses **simulated data**
([data/mock_debtors.csv](data/mock_debtors.csv)) generated by
[src/simulate.py](src/simulate.py); the true mechanism is stored in
[data/truth.json](data/truth.json).

## Data

8000 simulated debtors with the input columns and targets listed in Usage. Amounts are
log-normal and skewed; income is missing more often for the unemployed; a third of the
debtors have no debt with other creditors.

Simulated mechanism: a monthly hazard of the first payment rises with income and an
unobserved **willingness to pay**, falls with unemployment, debt with other creditors
relative to income and the age of the case, and peaks at middle age. Willingness is not
in the data — it shows only through past payments — so no model can reach the true
probabilities. After the first payment a debtor keeps paying with probability 0.7.
Payers: 4.9 % within 3 months, 8.4 % within 6, 15.0 % within 12.

`--snapshot later` simulates the population a year on (older cases, higher incomes,
lower payment rate) for out-of-time validation and drift monitoring.

## Solution

1. **Feature engineering** ([src/features.py](src/features.py)) — a scikit-learn
   transformer, fitted on training data only:
   - binary flags for any payment in the past 3 / 6 / 12 months and for missing values;
   - *wealth* — income accumulated over life, the cumulative sum over age of mean and
     median income per age;
   - 33 financial ratios: debt / income, debt / wealth, payments / income,
     payments / wealth, payments / debt.

   Missing values are not imputed: both models handle them natively, and a missing
   income is informative in itself.
2. **Payment likelihood** ([src/model.py](src/model.py)) — gradient boosting
   (scikit-learn `HistGradientBoostingClassifier` or XGBoost, 100 trees of depth 2,
   learning rate 0.1), one classifier per horizon, chained as a discrete-time hazard
   model: the 6-month model learns from debtors who did not pay within 3 months, the
   12-month model from those who did not pay within 6 months. This guarantees
   P(3 months) ≤ P(6 months) ≤ P(12 months).
3. **Calibrated probabilities** — the models are trained on the true class ratio, so
   the output is a real likelihood. Optional re-balancing (`--balance weight|down`) is
   followed by a prior correction p = βp′ / (βp′ − p′ + 1), where β is the weight of
   non-payers relative to payers in training.
4. **Expected recovery** ([src/recovery.py](src/recovery.py)) — two-part model:
   E[amount] = P(payment) × E[amount | payment], the second part a gamma regression on
   payers.
5. **Evaluation** ([src/train.py](src/train.py)) — 5-fold stratified cross-validation.
   A collection team has limited capacity, so instead of a fixed 0.5 threshold the
   main business metric is the share of all payers found among the top 10 % / 20 %
   debtors by predicted probability. Ranking quality is measured by ROC-AUC and PR-AUC,
   probability quality by Brier score and calibration (mean predicted / observed rate).
6. **Feature importance** ([src/importance.py](src/importance.py)) — each input
   column, with all features derived from it, is shuffled in a 30 % hold-out set; the
   drop of ROC-AUC is its importance.

## Results

On mock data, `HistGradientBoostingClassifier`, chained horizons, no re-balancing,
5-fold stratified CV (± is two standard deviations across folds):

| Horizon | ROC-AUC | True-probability ROC-AUC | PR-AUC | Calibration | Payers in top 10 % | Payers in top 20 % |
|---|---|---|---|---|---|---|
| 3 months | 0.69 ± 0.07 | 0.84 | 0.11 ± 0.05 | 1.03 ± 0.45 | 27 % ± 8 | 46 % ± 15 |
| 6 months | 0.69 ± 0.05 | 0.84 | 0.17 ± 0.06 | 1.01 ± 0.26 | 25 % ± 10 | 44 % ± 9 |
| 12 months | 0.70 ± 0.02 | 0.84 | 0.29 ± 0.04 | 1.00 ± 0.04 | 24 % ± 5 | 41 % ± 4 |

The true-probability ROC-AUC uses the simulated hazard including the unobserved
willingness, so it is an upper bound no model on the observed columns can reach.

- **Expected recovery:** the top 10 % / 20 % debtors ranked by expected amount bring
  37 % / 56 % of the amount paid within 12 months, against 24 % / 41 % when ranked
  by probability alone.
- **Feature importance** (drop of ROC-AUC, 12 months) recovers the simulated drivers:
  income 0.092, past payments in 12 months 0.071 (the proxy for willingness), case age
  0.020, age 0.007; the columns without an effect (principal, interest rate) are near 0.
  The effect of debt with other creditors is weaker than simulated (0.002).
- **Re-balancing:** with `--balance down` or `weight` the prior correction is only
  approximate — mean predicted probability up to 20 % off the observed rate in CV, more
  on small samples — so the default is training on the true class ratio.
- **Out of time** (train on the earlier snapshot, test on `--snapshot later --seed 1`):
  ROC-AUC 0.69, but calibration 1.11–1.26 — the model over-predicts after the payment
  rate falls. `monitor.py` flags the older cases (`case_age_months`, PSI 1.65) as a large
  shift, the signal to retrain.

## Deployment

Collection planning is periodic, so the model is deployed as a **monthly batch job**:
score the current snapshot, hand the ranked list to the collection team, monitor, retrain.

| Step | Script | What it does |
|---|---|---|
| Validate input | [src/schema.py](src/schema.py) | required columns, numeric types, no negative amounts, plausible age, binary and nested targets; all problems reported at once. Missing inputs are allowed. |
| Out-of-time check | [src/validate_time.py](src/validate_time.py) | train on an earlier snapshot, evaluate on a later one, before the model goes live |
| Train and save | [src/train.py](src/train.py), [src/recovery.py](src/recovery.py) | `--output` saves the model with metadata: training time, settings, library versions, CV scores, reference profile of the inputs |
| Score | [src/predict.py](src/predict.py) | probabilities, expected amounts and contact priority per debtor |
| Monitor | [src/monitor.py](src/monitor.py) | PSI per input column and missing shares against the training profile, mean predicted probability vs training |
| Package | [Dockerfile](Dockerfile) | Python 3.11 image with the scripts; the scheduler (cron, Airflow, …) runs it monthly |

In production:

- **Retrain** quarterly or when `monitor.py` reports a large shift (PSI > 0.25); promote
  the new model only if it beats the current one out of time on the latest snapshot.
- **Ground truth arrives late** — 3, 6 and 12 months after scoring. Once it does, compute
  the `train.py` metrics per scoring month to see real performance and calibration.
- **Keep a random control group** of debtors contacted regardless of score: otherwise
  future training data only contains outcomes of debtors the model chose, and the
  model's view of the others becomes biased. The control group also measures the real
  gain: amount recovered per contact, top-ranked vs random.
- **Pin versions** for the deployed image (e.g. `pip freeze` into a lock file);
  `requirements.txt` here lists packages only.

## Model card

- **Purpose:** prioritise debtors for collection contact by likelihood and expected
  amount of payment. Ranking support for people planning the work — not an automatic
  decision about an individual.
- **Data:** one snapshot of debtor records; debt, income and payment-history columns.
- **Performance:** measured by `train.py` (CV) and `validate_time.py` (out of time);
  probabilities are calibrated on the training snapshot. See Results for scores on mock data.
- **Limitations:**
  - all records come from one snapshot date, so cross-validation shows how well the
    model generalises to other debtors, not to the future — check with
    `validate_time.py` before use;
  - no hyperparameter tuning;
  - debtor age is an input: depending on the jurisdiction, using it for prioritisation
    may be restricted, so check score distributions across age groups.

## Usage

Input is a CSV with the columns `case_age_months, interest_rate, principal,
principal_interest, balance, age, income, external_debt, paid_amount_past_3m,
paid_amount_past_6m, paid_amount_past_12m`, targets `paid_next_3m, paid_next_6m,
paid_next_12m` and, for `recovery.py`, amounts `amount_next_3m, amount_next_6m,
amount_next_12m`. Other columns are ignored; an `id` column is copied to the scores.
The mock data has this format; replace it with your own snapshot.

```sh
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
pytest tests

cd src
# mock data (already in data/), and a later snapshot for out-of-time checks
python simulate.py --output ../data/mock_debtors.csv --truth ../data/truth.json
python simulate.py --output ../data/mock_later.csv --snapshot later --seed 1

# development
python train.py --input ../data/mock_debtors.csv                # payment likelihood, CV
python train.py --input ../data/mock_debtors.csv --model xgb --balance down --horizons independent
python recovery.py --input ../data/mock_debtors.csv             # expected recovery, CV
python importance.py --input ../data/mock_debtors.csv
python validate_time.py --train ../data/mock_debtors.csv --test ../data/mock_later.csv

# final models
python train.py --input ../data/mock_debtors.csv --output model.joblib
python recovery.py --input ../data/mock_debtors.csv --output recovery.joblib

# monthly run
python monitor.py --model recovery.joblib --input ../data/mock_later.csv
python predict.py --model recovery.joblib --input ../data/mock_later.csv --output scores.csv
```

With Docker:

```sh
docker build -t debt-payment-likelihood .
docker run --rm -v "$PWD/data:/data" debt-payment-likelihood \
    predict.py --model /data/recovery.joblib --input /data/snapshot.csv --output /data/scores.csv
```
