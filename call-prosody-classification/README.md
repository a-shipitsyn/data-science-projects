# Call prosody classification

Predict whether a sales phone call ends in a purchase from how the two
speakers sound: pitch, loudness, formants, speech rate and laughter.

*Independent prototype, not the client system. It runs on simulated data, so its scores are not comparable with results on real calls.*

## Task

Each sample is a two-channel phone-call recording (one speaker per channel)
with a binary label: **1 — the customer made a purchase, 0 — no purchase**.

From acoustic and prosodic features of each speaker — pitch, energy, formants,
voicing, speech rate, laughter — and of the ratios between the speakers, for the
whole call and for its three equal time segments, build a model that predicts the
label and identify which features matter most. Purchases are a small minority of
calls, so the classes are strongly imbalanced.

No original data is included in this repository. Simulated call features are
generated by [src/simulate.py](src/simulate.py) (the CSV, about 6 MB, is not stored);
the true mechanism is in [data/truth.json](data/truth.json).

## Data

600 simulated calls in the output format of `audio_features.py`, 17.8 % purchases.
Each speaker has their own voice (low or high pitch, formants rising with pitch,
loudness, speech rate); every third of the call varies around it, and the full-call
features combine the thirds. In 4 % of calls one speaker is silent in one third, which
gives null ratios as in real recordings.

Simulated mechanism: an unobserved **rapport** drives the purchase and leaves weak
traces, mostly at the end of the call — speaker B's pitch, voicing share and energy rise,
speaker A's pitch varies more, and laughter is more likely. The other features carry no
signal. The traces are small against the differences between voices, so the label can
only be partly recovered: the true probabilities reach ROC-AUC 0.83 and F1 0.55 at the
best threshold, an upper bound for any model.

## Solution

1. **Feature extraction** ([src/audio_features.py](src/audio_features.py)) — generic
   extractor of the model input from two-channel mp3 / wav calls with librosa:
   pYIN pitch, RMS energy, LPC formants, voicing, heuristic laughter detection;
   for the full call and per third of the call; ratios between the speakers.
2. **Preprocessing** ([src/preprocess.py](src/preprocess.py)) — flatten the per-region
   features into a table with columns `<source>__<region>__<feature>`, where source is
   `speaker_a`, `speaker_b` or `ratio` (a / b), region is `full`, `start`, `middle` or `end`
   (3 sources × 4 regions × 22 features = 264 columns),
   drop columns with more than 80 % missing values, impute the rest with KNN (k = 3).
3. **Logistic regression** ([src/logistic_regression.py](src/logistic_regression.py)) —
   StandardScaler → PCA (15 components) → LogisticRegression with balanced class weights.
   F1-score is used because of the class imbalance. Feature importance by permutation
   on the full data set (too few positives for a hold-out set).
4. **Neural network** ([src/neural_network.py](src/neural_network.py)) — PyTorch MLP
   (3 hidden layers × 60, ReLU, dropout 0.1), BCE loss weighted by the class ratio,
   stratified cross-validation.

Also tried without improvement: CatBoost, Random Forest, Histogram Gradient Boosting,
polynomial features.

## Results

On mock data, 4-fold CV, F1-score (± is two standard deviations across folds):

| Model | F1-score |
|---|---|
| True probabilities, best threshold (upper bound) | 0.55 |
| Logistic regression (scaler + PCA 15) | **0.45 ± 0.12** |
| MLP (3 × 60), raw features | 0.25 ± 0.17 |

- **Logistic regression** gets most of the recoverable signal.
- **The MLP** is weaker here: on raw features of very different scales (energy ~0.05,
  pitch ~200 Hz) 10 epochs at learning rate 1e-4 are not enough to learn the small
  traces.
- **Permutation importance** on the full data set does not recover the simulated
  drivers: with 260 features and 600 calls the model without PCA overfits, and noise
  features fill the top of the ranking. Of the true drivers only speaker B's pitch at the
  end ranks high (17th), laughter flags follow (41st and lower). Feature rankings from this
  method need a hold-out set or repeated CV to be trusted.

## Project structure

```
call-prosody-classification/
├── README.md
├── requirements.txt
├── data/
│   └── truth.json              # true mechanism, purchase rate, upper bounds
└── src/
    ├── simulate.py             # mock data in the audio_features.py format
    ├── audio_features.py       # mp3 / wav calls → features.csv
    ├── preprocess.py           # features.csv → flat, imputed clean_data.csv
    ├── logistic_regression.py  # main model, CV F1, permutation importance
    └── neural_network.py       # PyTorch MLP, CV F1
```

## Usage

```sh
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cd src

# 1. extract features from recordings (labels.csv: file,label)
python audio_features.py --input calls/ --output features.csv --labels labels.csv
#    or simulate them
python simulate.py --output features.csv --truth ../data/truth.json

# 2. flatten and impute
python preprocess.py --input features.csv --output clean_data.csv

# 3. models
python logistic_regression.py --input clean_data.csv
python neural_network.py --input clean_data.csv
```
